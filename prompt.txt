============================================================
MOST IMPORTANT REQUIREMENT
==========================

The system must obey this invariant:

NO RELEVANT EVIDENCE
↓
NO GROUNDED BIS CLAIM
↓
NO CITATION

A vector database returning a document does NOT mean that the document is relevant.

The LLM must NEVER convert irrelevant retrieved documents into authoritative-looking BIS answers.

============================================================
KNOWN QA EVIDENCE
=================

The existing system already handles some unknown-standard cases correctly.

For example:

"What is IS 99999:2026?"

currently produces:

* Retrieval=True
* Insufficient=True
* 0 citations
* safe abstention

So DO NOT destroy the existing abstention mechanism.

The major bug is specifically that product-discovery/general-query paths can bypass proper evidence validation.

Examples of failures include:

"What BIS standard covers teleportation machines?"

"What BIS standard covers invisible glass?"

"Tell me the mandatory QCO for a product called XYZ-999."

"Give me the exact BIS clause for a technology that does not exist in the knowledge base."

"What is the BIS standard for a flying car?"

These currently retrieve unrelated documents such as:

* BIS Act 2016
* Scheme-I
* QCO Framework
* unrelated Indian Standards

and then generate citations.

THIS IS THE PRIMARY BUG.

PHASE 2 — FIX RETRIEVAL GATING
==============================

Implement a strict evidence gate.

The retrieval system must distinguish:

1. candidate documents
2. relevant documents
3. verified evidence

Do NOT treat top-K retrieval as verified evidence.

Every retrieved document must pass a relevance threshold.

Support the vector database's actual metric:

* cosine similarity
  OR
* cosine distance
  OR
* inner product
  OR
  whatever the project currently uses.

Do not assume the metric.

Inspect the implementation first.

Create configurable settings such as:

RAG_TOP_K
RAG_MIN_SCORE
RAG_MAX_CONTEXT_DOCUMENTS

Do not scatter hardcoded thresholds throughout the project.

If all retrieved documents fail relevance filtering:

return an explicit state:

{
"has_evidence": false,
"documents": [],
"reason": "NO_RELEVANT_EVIDENCE"
}

The LLM must receive ZERO irrelevant documents in this case.

============================================================
PHASE 3 — ADD SEMANTIC EVIDENCE VALIDATION
==========================================

A similarity threshold alone is NOT sufficient.

Example:

Query:

"What BIS standard covers teleportation machines?"

A generic BIS Act document may have reasonable semantic similarity because the query contains "BIS standard".

That does NOT mean it supports teleportation machines.

Therefore implement a second evidence check.

The evidence must actually relate to the requested subject.

For product-specific questions, verify that retrieved evidence contains/supports the requested product or product category.

For standard-specific questions, verify:

* requested IS number
* requested part
* requested clause
* relevant content

For QCO questions, verify:

* requested product
* QCO evidence
* relevant regulatory context

If the evidence is only generic BIS information:

DO NOT use it to answer the product-specific question.

============================================================
PHASE 4 — PRODUCT ENTITY / SUBJECT EXTRACTION
=============================================

Before retrieval, identify the actual subject of the query.

Example:

"What BIS standard covers teleportation machines?"

Extract:

intent = PRODUCT_STANDARD_DISCOVERY
subject = teleportation machines

Then retrieval must answer:

"Do my sources contain evidence about teleportation machines?"

NOT merely:

"Do my sources contain the words BIS and standard?"

Similarly:

"What is the mandatory QCO for XYZ-999?"

must identify:

product = XYZ-999
intent = QCO

and verify evidence specifically related to XYZ-999.

If no evidence exists:

ABSTAIN.

Do NOT use the generic QCO Framework as proof that XYZ-999 has a QCO.

============================================================
PHASE 5 — HARD ABSTENTION
=========================

If:

has_evidence == false

then the response generator MUST NOT produce a grounded BIS answer.

Return a safe abstention.

Example:

"I couldn't find relevant BIS evidence for this product in my available sources. I don't want to invent a standard, QCO, clause, or citation. If you provide a product category, IS number, or additional details, I can help narrow it down."

Do not claim:

"There is no BIS standard."

unless the evidence actually proves that.

The correct statement is:

"No relevant evidence was found in the available sources."

============================================================
PHASE 6 — FIX CITATION HALLUCINATION
====================================

Citations must be generated ONLY from retrieved evidence.

Every citation must have a valid source ID.

Every source ID must correspond to a document actually retrieved.

Every cited claim must be supported by the cited evidence.

Implement:

LLM OUTPUT
→ PARSE CITATIONS
→ VALIDATE SOURCE ID
→ VERIFY RETRIEVED SOURCE
→ VERIFY EVIDENCE
→ ACCEPT / REJECT

If invalid:

DO NOT create a generic fallback citation.

Instead:

1. regenerate using verified evidence

OR

2. abstain.

Never generate citations such as:

"BIS Act 2016"

"Scheme-I"

"QCO Framework"

simply because they exist in the database.

Their presence in the database does not make them evidence for the current question.

PHASE 7 — FIX THE QUERY REWRITER
================================

THIS IS A MAJOR BUG.

The current system generates queries such as:

"3 - What documents do I need?"

and:

"What is FMCS? - Tell me Clause 999 of IS 1293."

This is broken.

REMOVE raw string concatenation.

Do NOT do:

previous_query + " - " + current_query

Do NOT do:

previous_message + current_message

Instead maintain structured conversation state.

Example:

{

"active_standard": null,
"active_topic": "battery certification",
"active_intent": "CERTIFICATION_GUIDANCE",
"clarification_pending": false
}

The current query must be resolved against this structured state.
